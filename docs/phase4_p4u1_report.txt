2. APPROVED DECISIONS IMPLEMENTED (A1–A6, from the plan)
-----------------------------------------------------------------------
A1 PERMISSIONS: exactly pos:read | pos:create | pos:manage (no
   pos:register). Role defaults: owner semantic-all; admin += all three;
   employee += pos:read ONLY. pos:create = register device + open
   session; pos:manage = suspend/resume/retire, rotate credential,
   close session; pos:read = list/get.
A2 DEVICE CREDENTIAL: server-issued 384-bit random secret
   (crypto.randomBytes(48) -> base64url), stored ONLY as sha256 hex
   (PosDevice.credentialHash, UNIQUE), returned in plaintext EXACTLY
   ONCE in the register/rotate-credential responses, never in any
   list/read endpoint, never logged. verifyCredential() provides
   constant-time (timingSafeEqual) digest comparison for the future
   X-POS-Device-Credential sync header (P4-U5; not implemented here).
A3 SESSION CLOSE: bare OPEN -> CLOSED lifecycle; no financial summary
   fields in P4-U1.
A4 REGISTRATION AUTHORITY: pos:create only — owner/admin allowed,
   employee/cashier NOT allowed (employee default is pos:read only).
A5 STORE BINDING: permanent. storeId is not patchable (whitelist 400);
   moving a terminal = retire + re-register. Sessions inherit the
   DEVICE's store; client-supplied storeId is rejected with 400.
A6 DEVICE LIFECYCLE: ACTIVE <-> SUSPENDED; ACTIVE|SUSPENDED -> RETIRED
   (terminal). RETIRED is checked FIRST for every action (all
   transitions + rotation on a retired device -> 409 'Device is already
   retired'). No hard-delete endpoint; no transition out of RETIRED.

3. ARCHITECTURE
-----------------------------------------------------------------------
New module src/pos/ (mirrors the Phase 3 module conventions):
  - PosDeviceService: registration (store resolved via tenant-scoped
    lookup, foreign/unknown -> 404 'Store not found', the Asset.storeId
    precedent), keyset-paginated list with status filter, get, rename
    (PATCH), guarded lifecycle transitions, guarded credential rotation,
    constant-time verifyCredential.
  - PosSessionService: open (device must be ACTIVE; store derived from
    the device; cashier = authenticated principal; one-open-per-device
    enforced), get, guarded close (re-close -> 409).
  - PosController: full guard chain JwtAuthGuard -> TenantResolutionGuard
    -> PermissionsGuard + TenantContextInterceptor + whitelist/transform/
    forbidNonWhitelisted ValidationPipe (PaymentController pattern).
  - PosModule: imports TenantModule + RbacModule; exports both services.

Reused established patterns: credential hashing (RefreshToken sha256),
guarded updateMany transitions (Payment T2), P2002 -> 409 mapping,
keyset pagination module, app-side same-tenant reference resolution.

4. SCHEMA (as implemented)
-----------------------------------------------------------------------
enum PosDeviceStatus { ACTIVE SUSPENDED RETIRED }
enum PosSessionStatus { OPEN CLOSED }

PosDevice: id cuid, tenantId, storeId (Store, RESTRICT), name
  (UNIQUE(tenantId,name)), status (default ACTIVE), credentialHash
  (UNIQUE, sha256 hex), lastSeenAt? (for P4-U5 sync), timestamps;
  indexes [tenantId], [tenantId,createdAt,id] (keyset parity), [storeId].

PosSession: id cuid, tenantId, deviceId (PosDevice, CASCADE), storeId
  (denormalized from device, Store RESTRICT), userId (cashier, User
  CASCADE), status (default OPEN), openedAt, closedAt?, timestamps;
  indexes [tenantId], [tenantId,createdAt,id], [deviceId,status],
  [userId]. CHECK (closedAt IS NULL OR closedAt >= openedAt).

Database-only constraints (handwritten SQL):
  - PARTIAL UNIQUE INDEX PosSession_one_open_per_device ON
    PosSession(deviceId) WHERE status = 'OPEN' — the DB arbitrates the
    dual-open race (deliberately stricter than the tolerated U5 cart
    race; a terminal is single-cashier-at-a-time).
  - Store delete is RESTRICTed while devices/sessions reference it
    (Category/Product P2003 precedent — verified in integration tests).

Tenant scoping: 'PosDevice','PosSession' added to TENANT_SCOPED_MODELS
(15 tenant-scoped models). tenantId always server-derived from the
AsyncLocalStorage context; fail-closed; uniform cross-tenant 404.

6. API SURFACE
-----------------------------------------------------------------------
POST   /pos/devices                    pos:create  201 {device + credential}
GET    /pos/devices                    pos:read    200 {data,meta.nextCursor} (status filter)
GET    /pos/devices/:id                pos:read    200 DeviceSummary (never credential fields)
PATCH  /pos/devices/:id                pos:manage  200 (name only; storeId/status -> 400)
POST   /pos/devices/:id/suspend        pos:manage  200 ACTIVE->SUSPENDED
POST   /pos/devices/:id/resume         pos:manage  200 SUSPENDED->ACTIVE
POST   /pos/devices/:id/retire         pos:manage  200 *->RETIRED (terminal)
POST   /pos/devices/:id/rotate-credential pos:manage 200 {device + NEW credential}
POST   /pos/sessions                   pos:create  201 SessionSummary
GET    /pos/sessions/:id               pos:read    200 SessionSummary
POST   /pos/sessions/:id/close         pos:manage  200 OPEN->CLOSED

Error semantics: unknown/foreign ids -> uniform 404 ('Pos device not
found' / 'POS session not found' / 'Store not found'); state-machine
violations -> 409 ('Device is not active' / 'Device is not suspended' /
'Device is already retired' / 'Device already has an open session' /
'Only open sessions can be closed'); duplicate name -> 409; whitelist
violations -> 400.

7. SECURITY MODEL (VERIFIED BY TESTS)
-----------------------------------------------------------------------
  - Tenant isolation: both models centralized-scoped; cross-tenant
    GET/PATCH/suspend/retire/rotate/session-open/session-close all
    return uniform 404 and leave the owning tenant's rows untouched
    (direct DB verification); ambient-context direct Prisma reads
    return null under the foreign tenant.
  - Credential security: plaintext appears exactly once; the stored row
    equals sha256(credential) and never the plaintext; no read/list
    endpoint exposes credential or credentialHash; rotation replaces
    the hash atomically and is guarded against concurrent retire.
  - IDOR/injection: tenantId, status, credential(Hash), id, timestamps,
    unknown fields -> 400 on create; storeId/userId on session open ->
    400 (store comes from the device); PATCH storeId/status -> 400.
  - RBAC: A1 matrix behavior-verified — employee (pos:read only) reads
    but gets 403 on register/retire/open/close; create-only member can
    register + open but not read/manage; owner semantic-all walks the
    full lifecycle with zero grants.

-----------------------------------------------------------------------
8. LIFECYCLE & CONCURRENCY BEHAVIOR (TESTED)
-----------------------------------------------------------------------
  - A6 matrix verified end-to-end: suspend -> resume -> retire; every
    invalid edge -> its documented 409; RETIRED rejects suspend/resume/
    retire/rotation with 'Device is already retired'.
  - Suspended devices cannot open sessions (409 'Device is not
    active'); resume restores opening.
  - Session close is guarded; re-close -> 409; closedAt set; CHECK
    closedAt >= openedAt enforced at the DB.
  - DETERMINISTIC RACES (real HTTP, no mocks/sleeps):
      * two concurrent session opens on one device -> exactly
        [201, 409] ('Device already has an open session'), exactly one
        OPEN row — the partial unique index arbitrates;
      * two concurrent retires on one device -> exactly [200, 409] —
        the guarded updateMany arbitrates; final row RETIRED.
